開いている VS Code のウィンドウを検出し、プロジェクト名のボタンとして並べる Windows 常駐ツール（C# / WPF / .NET）。ボタン押下で対応ウィンドウを前面化する。詳細設計は [design-vscode-selector.md](design-vscode-selector.md) を参照。

## 1. ウィンドウ検出（列挙・フィルタ）

`EnumWindows` の結果（Z オーダー順）から、次をすべて満たすトップレベルウィンドウを VS Code とみなす。

- 可視・オーナーなし・ツールウィンドウでない・タイトルが空でない
- DWM で cloak されていない（別仮想デスクトップ等）
- クラス名が `Chrome_WidgetWin_1`
- exe 名が `Code.exe` / `Code - Insiders.exe` / `VSCodium.exe`、または設定 `extraProcessNames` に一致（拡張子あり/なし両方可、大小文字無視）
- `OpenProcess` に失敗した場合（管理者権限で動く VS Code 等）は、タイトル末尾がアプリ名（`Visual Studio Code` / `Visual Studio Code - Insiders` / `VSCodium` / `Code - OSS`）なら採用し、ログに 1 行記録する

エディション（Stable / Insiders / VSCodium）は exe 名から判定する。

## 2. タイトル解析

タイトル文字列からプロジェクト名を取り出す。例外は投げず、解析できない場合はタイトル全文を表示名にする。

1. 設定 `titlePattern` があり、名前付きグループ `project` がマッチすればそれを採用する
2. 末尾のアプリ名部分を除去する（アプリ名のみのタイトルは「フォルダなし」）
3. 先頭の `[Administrator] `、未保存マーク `● ` / `* ` を除去する
4. 設定 `titleSeparators`（既定 `" - "`）で分割し、最後の要素をプロジェクト名とする
5. 末尾の `[...]` をリモートラベルとして分離し WSL / SSH / Dev Container / Codespaces / その他に分類、` (Workspace)` はワークスペースとして除去する
6. 区切りが無く `Welcome` / `Get Started` / `Settings` / `Extension: ...` のみのタイトルは `(No Folder)` とする

表示名は 40 文字を超えると 39 文字 + `…` に切り詰める。正規表現は 100ms でタイムアウトする。

- 要確認: 日本語 UI の VS Code では管理者表示や `(Workspace)` が日本語表記になる可能性があり、現状は英語表記のみ除去する。

## 3. 同名プロジェクトの区別

表示名が重複する場合、次の順で区別する。

1. リモートラベルがあれば ` [ラベル]` を付ける
2. まだ重複していれば ` (Insiders)` / ` (VSCodium)` を付ける（Stable は付けない）
3. まだ重複していれば HWND 昇順で連番を振り、2 番目以降に ` #N` を付ける。連番は HWND ごとに保持し、ウィンドウが閉じられるまで変わらない

## 4. 並び順と更新

- 並び順: 設定 `sortOrder` が `name`（既定）なら表示名の昇順（大小文字無視・安定ソート）、`zorder` なら列挙順
- 更新トリガー: WinEvent フック（`EVENT_OBJECT_SHOW` / `DESTROY` / `NAMECHANGE`、専用スレッドで受信）と定期ポーリング（通常 2000ms、最小化中 5000ms）を併用する。フック登録に失敗してもポーリングのみで動く
- 両トリガーは 250ms のデバウンス窓で 1 回の列挙にまとめる。列挙が 50ms を超えたらログに警告する
- 一覧は HWND をキーに差分適用し、変化の無いボタンはそのまま残す
- 列挙失敗時は前回の一覧を残し、ステータスに「ウィンドウ一覧の取得に失敗しました。前回の一覧を表示しています。」を表示する

## 5. ボタン押下（前面化 / トグル最小化）

- **トグル最小化**: 押す直前に前面だった（自プロセス以外の）ウィンドウが押したボタンの VS Code で、かつ有効・未最小化なら、前面化せず最小化する。直前の前面ウィンドウは `EVENT_SYSTEM_FOREGROUND` フックで記録する（押下時は自ウィンドウが前面になるため）
- **前面化**: 対象が消えた・PID やクラス名が変わった場合は一覧から外して再列挙する。最小化中なら元に戻し、`SetForegroundWindow` を最大 4 段階（単純呼び出し → `AllowSetForegroundWindow` → Alt キー送出 → `AttachThreadInput`）で 50ms 間隔で試す
- 全段階で失敗した場合はタスクバーを点滅させ、ステータスに「前面に出せませんでした。タスクバーから切り替えてください。」を 3 秒間表示する
- 前面化に成功し、設定 `hideOnActivate` が true なら自ウィンドウを最小化する

## 6. 画面

- 枠なしウィンドウ（タイトルバーなし、1px のグレー枠、リサイズ可、最大化不可）。既定サイズは 520×384
- **擬似バー**（幅/高さ 24）を短辺に置く。横長なら左端の縦バー、縦長なら上端の横バーに切り替わる。バーをドラッグするとウィンドウを移動でき、バー上の ✕ ボタンで終了する
- 最小サイズはボタン 1 個分: 縦長時 164×62、横長時（左バー分を足して）幅 188
- ボタン（150×48、余白 6）を折り返して並べ、上段にプロジェクト名（太字）、下段にエディションとリモート種別（小文字、例 `stable / wsl: ubuntu`）を表示する。ツールチップはタイトル全文。最小化中のウィンドウは灰色文字
- スクロールバーは表示しない（ホイール等でスクロールは可能）
- ステータス表示はリスト下端に重ねて表示し、メッセージが無いときは隠す
- 一覧が空なら「開いている VS Code がありません」を表示する
- キー操作: `Ctrl+1`〜`Ctrl+9` で N 番目を押下、`Enter` でフォーカス中のボタンを押下、`Esc` で自ウィンドウを最小化
- 設定 `topmost` が true なら最前面に固定する
- 要確認: `LayoutMath`（列数・行数の計算）はスクロールバー幅・下部ステータスバー高さを差し引く旧レイアウト前提のままで、テストからのみ参照されている。

## 7. 設定

`%APPDATA%\VsCodeSelector\settings.json`（コメント・末尾カンマ可）。ファイルが無い・壊れている・型が違うキーは既定値を使い、警告をログに残す。ファイルを書き換えることはない。

| キー | 型 | 既定 | 内容 |
|---|---|---|---|
| `titleSeparators` | 空でない文字列の配列 | `[" - "]` | タイトルの区切り文字 |
| `titlePattern` | 文字列 / null | null | `project` グループ付き正規表現。不正なら null 扱い |
| `extraProcessNames` | 文字列の配列 | `[]` | 追加で VS Code とみなす exe 名 |
| `sortOrder` | `"name"` / `"zorder"` | `"name"` | 並び順 |
| `topmost` | bool | false | 最前面固定 |
| `hideOnActivate` | bool | false | 前面化後に自ウィンドウを最小化 |

## 8. ログ

`%LOCALAPPDATA%\VsCodeSelector\logs\app-YYYYMMDD.log` に日次で追記する（UTF-8、レベル DEBUG/INFO/WARN/ERROR）。古いログは削除しない。ログ書き込みの失敗でアプリは止まらない。
